# Безопасность MVP

## Границы доступа

Проверки стоят в Payload Access Control и серверных hooks. Скрытие кнопок в админке не считается защитой. У редактора два ограничения: назначенные города и разрешённые разделы. Проверяются исходная запись и новый город, поэтому перенос чужой записи в свой город не обходит права. Для документов используется актуальная привязка родительского врача; смена города врача сразу отзывает доступ прежнего редактора.

Сотрудник не может менять собственные роль, города и разрешения. Публичная регистрация, создание сотрудников и произвольное создание отзывов через стандартный REST API закрыты. Все публичные запросы Local API выполняются с `overrideAccess: false`. Повышенные права используются только при bootstrap, записи аудита и в отдельном обработчике формы с жёстким списком полей.

## Документы и фотографии

Карточка услуги объединяет цены без переноса их в недоверенный JSON: виртуальное поле сохраняется в прежних записях цен. Сервер проверяет каждый город, принадлежность филиалов и тип цены. Изменение своего города не удаляет записи остальных городов; ошибка вложенной записи откатывает всю операцию. Название и раздел общей услуги защищены отдельными полевыми правами.

Публичные корпоративные PDF в `public/documents` — фиксированные копии документов с действующего сайта. Для модалок заранее отрисованы страницы; Google Drive и PDF-плагин браузера не нужны. Это не каталог загрузок сотрудников. Видео RUTUBE загружаются в разрешённом iframe только после нажатия пользователя. Шрифт обслуживается локально. Внешние аватары админки отключены.

Файлы хранятся в `STORAGE_DIR`, вне `public`. Разрешены только JPEG/PNG/PDF до 8 МБ; сверяются MIME и сигнатура. Изображения декодируются с ограничением числа пикселей и перекодируются в JPEG без исходных метаданных. Загрузка по произвольному URL отключена. PDF проходят штатную проверку Payload и отдаются скачиванием с `nosniff`, `Content-Disposition: attachment` и CSP sandbox. Документ опубликованного врача не виден, пока не опубликован сам документ; при снятии врача с публикации закрывается и файл. Это не заменяет антивирусную проверку на рабочей инфраструктуре.

## Отзывы

Принимаются только ожидаемые поля JSON. Статус всегда `pending`, ответ отсутствует. Требуются согласие, подписанный токен формы, привязанный к HttpOnly SameSite cookie, корректный Origin и небольшой интервал после открытия формы. Токен одноразовый: уникальный ключ в PostgreSQL блокирует повторную запись, включая одновременные запросы. Применяются атомарные лимиты в PostgreSQL по сессии, всему сайту и, при доверенном proxy, по IP. Исходный IP не сохраняется — ключи считаются через HMAC. Лимиты работают между процессами; устаревшие записи очищаются.

Контакты, внутренние заметки, данные согласия и ключ отправки закрыты полевыми правами. Ключ отправки и данные согласия нельзя менять через API. Статус отзыва и публикация ответа независимы; ответ не публикует отклонённый отзыв. История изменений позволяет проследить модерацию. Публичный текст выводится как текст React, без вставки пользовательского HTML.

## Сессии и HTTP

Случайные секреты, часовой токен входа, блокировка после пяти неудачных попыток на 10 минут, HttpOnly cookies штатной авторизации Payload, Secure cookies в production, точный список доверенных Origin. Письма сброса пароля не выводятся в логи. GraphQL отключён. Присутствуют nonce CSP, запрет встраивания, ограничения browser permissions, `nosniff`, Referrer-Policy и запрет индексации демо. Для административных API установлен `no-store`. Reverse proxy должен обеспечивать TLS, HSTS и собственные лимиты на запросы и загрузки.

## Зависимости и ограничения

На момент проверки DOMPurify обновлён до 3.4.17, esbuild — до исправленной совместимой версии. В npm audit остались 7 сообщений низкого уровня, относящихся к deepmerge и использующим его пакетам Payload. Для deepmerge 4.3.1 upstream-исправления пока нет. В JSON-запросах API блокируются ключи `__proto__`, `constructor`, `prototype` и чрезмерная вложенность; это дополнительная защита, а не исправление стороннего пакета. Перед внешним размещением повторить audit и проверить появление исправления Payload/deepmerge. Высоких и критических сообщений в последней проверке нет.

MVP не хранит результаты исследований и не управляет записью в МИС. Рабочие формы, тексты согласий, сроки хранения и политика конфиденциальности требуют утверждения клиникой перед сбором реальных данных. Нынешняя страница политики прямо помечает демонстрационный режим. Резервное копирование, мониторинг, SMTP и антивирус на сервере должны быть настроены для выбранной среды.
